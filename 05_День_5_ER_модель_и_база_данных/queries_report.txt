qs1 = BarItem.objects.filter(

Запрос 3: Агрегация данных (Финансовые и производственные итоги клуба)
Бизнес-задача: Рассчитать сводные показатели по подтвержденным и завершенным бронированиям: суммарную выручку, количество сеансов, средний чек и максимальную стоимость бронирования.
Код запроса Django ORM:
qs3 = Booking.objects.filter(
    status__in=['CONFIRMED', 'IN_PROGRESS', 'COMPLETED']
).aggregate(
    total_bookings=Count('id'),
    total_revenue=Sum('total_cost'),
    avg_check=Avg('total_cost'),
    max_booking=Max('total_cost')
)
Сгенерированный SQL-запрос:
SELECT COUNT("club_booking_booking"."id") AS "total_bookings", SUM("club_booking_booking"."total_cost") AS "total_revenue", AVG("club_booking_booking"."total_cost") AS "avg_check", MAX("club_booking_booking"."total_cost") AS "max_booking" FROM "club_booking_booking" WHERE "club_booking_booking"."status" IN ('CONFIRMED', 'IN_PROGRESS', 'COMPLETED');
Результат выполнения агрегации:

— Средний чек бронирования в комплексе: 3 651.00 руб.
— Максимальная стоимость единичного бронирования: 6 469.50 руб.

Запрос 4: Выборка по связи «один ко многим» с select_related() (JOIN-оптимизация)
Бизнес-задача: Получить подтвержденные бронирования с немедленной сквозной загрузкой связанных объектов Клиента, Игрового ресурса и Категории зала в рамках ОДНОГО SQL-запроса с INNER JOIN (устранение проблемы N+1 запросов).
Код запроса Django ORM:
qs4 = Booking.objects.select_related(
    'client', 'resource', 'resource__category'
).filter(status='CONFIRMED').order_by('booking_date', 'time_start')[:5]

Запрос 5: Выборка по связи «многие ко многим» с prefetch_related() (Пакетная подгрузка M:M)
Бизнес-задача: Выгрузить завершенные сеансы боулинга с пакетной предварительной выборкой всех прикрепленных заказов бара (связь M:M) и проведенных фискальных платежей (связь 1:M).
Код запроса Django ORM:
qs5 = Booking.objects.prefetch_related(
    'bar_orders__bar_item', 'payments'
).filter(resource__category__code='BOWLING', status='COMPLETED').order_by('id')[:4]
Механизм исполнения: Django выполняет ровно 3 высокоскоростных SQL-запроса вместо десятков одиночных запросов:
1. Запрос к бронированиям дорожек боулинга:
   SELECT * FROM "club_booking_booking" INNER JOIN "club_booking_clubresource" ... WHERE code = 'BOWLING' AND status = 'COMPLETED' LIMIT 4;
2. Пакетный запрос M:M к заказам бара и позициям меню:
   SELECT * FROM "club_booking_bookingbarorder" INNER JOIN "club_booking_baritem" ... WHERE booking_id IN (1, 2, 3, 4);
3. Пакетный запрос к фискальным платежам 54-ФЗ:
   SELECT * FROM "club_booking_payment" WHERE booking_id IN (1, 2, 3, 4);
